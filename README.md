# AI Bot City Simulator — Smallville (frontend-only)

A living isometric city of autonomous agents. No backend, no database server, no account, no API key, no external AI. Simulation, memories, and persistence all run locally in the browser.

**Live:** https://ai-bot-city-simulator.vercel.app
**Current state (V5, 28 Oct 2026):** detailed procedural pixel-art citizens with idle blink and genuine 4-direction views, a tile-based connected road network, and the V3 building artwork preserved.

## Commands
```bash
npm install
npm run dev      # start, usually http://localhost:5173
npm run build    # typecheck + production build
npm run preview  # serve the production build
npm test         # Vitest unit tests
npm run test:e2e # Playwright (requires browsers: npx playwright install chromium)
```

## What is implemented
- Phaser 3 isometric city: Smallville with Neural Cafe, Central Park, Residential District, Town Hall, Corner Shop, Office Building, Restaurant, Bus Stop. Six buildings use generated image assets in `public/v3-assets/` (cafe, restaurant, shop, town hall, office, house); the rest of the city art is original procedural pixel art, bundled locally, no remote images at runtime.
- Connected road network (V4 fix): a tile-based road graph in `src/simulation/map.ts` linking every location entrance — north, west, shop, town hall and south roads plus the main cross — with sidewalks, curbs, dashed yellow centrelines aligned to the isometric axes, and crosswalks at the three 4-way intersections. No mid-ground dead ends.
- 24 seeded distinct agents with roles, personalities, needs (energy/hunger/mood/sociability/confidence), schedules, relationships, and memories. Characters are 24×32 procedural chibi sprites with 7 hair styles, 4 skin tones, 23 role palettes, collars, belts, shading, skirts, idle blink, walk animation and genuine 4-direction views; registry and inspector avatars render the same sprite grid.
- Terrain and vegetation: 4 deterministic variants each for grass, paving, park and sidewalk tiles; maple and birch trees alongside oak, pine and blossom; benches, streetlights, bins, planters, flowerbeds, fountain, parked cars, and a bus shelter.
- Real engine in `src/simulation/`: Perceive → needs → utility goal selection → A* pathfinding on walkable tiles only → movement → proximity interaction → event + memory. States: Idle, Walking, Commuting, Working, Eating, Resting, Socializing, Shopping, Waiting, Sleeping, Conversing. Time scale: 1 real second at 1× = 1 sim minute, so activities complete in a real run.
- Dashboard: top bar (pause, 1x/2x/4x/8x, Add Agent, tick, time), Agent Registry (search/filter/sort), live Metrics computed from state, Agent Inspector (follow, memories, relationships, pause/reset agent, personality slider), collapsible Event Console (search/filter, autoscroll, clear), and views City / Agents / Locations / Memories / Event Log / Settings that do not destroy the simulation (Phaser stays mounted, hidden, when another view is shown). On phones (<768px) the side panels start collapsed.
- Persistence: Dexie IndexedDB + localStorage, Zod-validated snapshots, Save/Load/Reset. Corrupt saves are rejected with a message, not loaded.
- Optional browser-local LLM: defined as off by default only in the sense that the rules engine is the sole decision loop; no LLM code path, download, or external call exists in this build. Conversation summaries are generated by local rules and are never described as LLM output.
- Hugging Face art pipeline (development-time only, `tools/asset-generation/`): SD 1.5 + pixel-art LoRA workflow for a Windows RTX 4050 machine, with `run-windows.bat` as the single-command launcher, validation, and integration scripts. No HF assets have been generated yet in this environment (no GPU here); the V5 HF prompt entries are pending. The deployed site never downloads or runs a model.
- Tests (as of V5): 44 unit tests and 6 Playwright e2e specs passing, including road-connectivity, asset, liveness, and pipeline tests.

## Limitations
- Agent sprites and most environment art are procedural pixel art, not hand-drawn or HF-generated sprite sheets; the HF-generated character/environment assets are still pending a run on a GPU machine.
- At fit-to-district zoom, agents still read small; close/follow zoom is where faces and clothing details read clearly.
- Canvas click hit-testing selects the nearest agent container in Phaser; precise pixel hit-testing is not implemented.
- Save/Load restores agents, memories, events, tick, and seed, but Phaser camera position is not persisted.
- GitHub pushes do not auto-deploy; production deploys are made with the Vercel CLI.
